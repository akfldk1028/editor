- User requires an always-visible ordinance section, readable provision cards, and full article text from the Law Agent. No parcel or jurisdiction hardcoding.
- Actual frontend ReviewTab now composes ReviewNavigation, SourceArticle and ReviewContext, with scoped review-reader.css. The searchable navigation lists all ordinance references, including unresolved references, then review groups. Selecting a reference fetches its original text. Statute refs with graph IDs fetch the entire article. Missing exact IDs are reported, not replaced by arbitrary search hits. This replaces the previous OrdinancePanel layout; public/previews HTML is not the product implementation.
- api/reference.ts uses the existing host ensure + platform ask doors, sends one selected reference with PNU and assessment date, and validates ordinance identity/article or statute graph ID before displaying the source. No direct browser call to agents.
- Name-only ordinances now use the same Law Agent law_ordinance tool with article='' to resolve dated edition metadata and the official full-ordinance URL. This is not an inline full-ordinance body endpoint: the existing tool returns no matches for empty article. Do not block these refs in the frontend or route them to generic statute search.
