# Packed terrain gate before building bake

From the editor app directory, run Bun `./tools/verify-ngii-terrain-only.ts` with explicit `--data-root`, `--work`, `--snapshot`, `--plan`, `--regions`, `--queue-inputs`, `--terrain`, `--terrain-receipt`, `--dem`, and `--python` paths. `--below-normal` lowers only its native child. The queue input is the existing completed source inventory pin: its source snapshot/plan/inventory bindings are verified independently of its old terrain identity. The NEW archive and receipt have their own SHA and source fingerprint checks.

The CLI reads canonical anchors through the existing snapshot reader, native heights through the unchanged persistent NativeWorker, and final packed PMTiles through the same resolved terrain contract. It does not read regional mesh candidates or substitute overlay-only samples. Native finite error over 0.5m fails; native NoData remains separately classified and cannot establish accuracy. No finite native evidence cannot pass. This does not verify mesh datums or geographic completeness; those gates remain mandatory.

The evidence directory must be separate from inputs. A writer lock, input stamps, native heartbeat, source fingerprints, 20GiB reserve and per-region checksummed receipts protect resume. A STOP file stops at a region boundary and full mode exits unsuccessfully unless complete/passed. Never remove a live lock. A changed code/source/archive pin requires a fresh evidence directory. `--region 14/13976/6335` is an explicit sample: samplePassed may be true but complete/passed remain false. Full mode omits `--region` and must cover every pinned inventory row. No service pointers are written.

After the full gate passes, bake new regional candidates against exactly that terrain SHA. Independently run `verify-ngii-national-heights.ts` afterward to retain the 0.01m published-component datum gate and 0.5m native/display gate. The terrain-only proof cannot replace that publication evidence.
