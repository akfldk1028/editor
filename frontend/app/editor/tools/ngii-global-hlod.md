# Candidate global NGII HLOD

`ngii-global-hlod.ts` builds a candidate-only hierarchy above the existing immutable regional v3 tilesets. It never modifies a regional payload, runtime hook, active catalog, terrain source, or release pointer.

Input JSON specifies pinned `sourcePlanSHA256`, `terrainSHA256`, and `regions: [{ owner: "14/x/y", folder, uri }]`. `folder` is a local input; `uri` is the deployment-relative or HTTP(S) regional tileset URL. All source receipts, footprint/tileset bytes, component counts, absolute ENU frames and full-shape bounds are verified. The output lives under `DATA_ROOT/world-buildings/national/<identity>/` with an immutable receipt. The output identity carries `implementationSHA256` (this file) and `lodCodeSHA256` (`generalize-buildings.ts`, `prebuilt-mesh.ts`), so a generalizer or mesh change without a revision bump cannot reuse old outputs; the release preparer pins `GLOBAL_HLOD_REVISION` (`ngii-global-generalized-quadtree-v2`). The CLI requires `--input` and `--data-root`; 20GiB reserve is enforced before writes.

Only z11-z13 carry content; z5-z10 are empty (buildings are a few pixels at most there) with error max(children, node width / 16), which only decides where z11 takes over. Each content node generalizes its children's content with `generalizeBuildings` (`features/world/lib/generalize-buildings.ts`) coarse to fine: eps starts at node width / 32 and halves down to node width / 256 (z13 ~ 15 m, z12 ~ 30 m, z11 ~ 60 m); z13 takes the regions' real component footprints, higher nodes their child nodes' output features. A merged block is kept only where it is mostly built: its members' real footprint area >= 0.2 of the block's area (`HLOD_MIN_COVERAGE`; measured: dense Busan/Gosan cores pass at eps 30-60, closing across fields and valleys stays far below). Members of a sparser block are retried at the next finer eps, and the dense members of the same group are generalized again alone and re-checked (dense and more than one member): a block that is then sparse or single also moves to the next eps, while the measured error of that second pass still includes it (conservative; requiring a fully clean pass left the Busan core unmerged in the scratch build). What is still sparse at the finest eps stays as its own footprint (its oriented box when within 25% of its footprint area; the box deviation enters the error). A footprint wider than the 64 eps cell is kept as itself at once, so no group's error raster grows far past the cell. Each pass groups by real height band (<7, 7-14, 14-28, 28-56, >=56 m, so towers are never averaged with houses) and by a 64 eps spatial cell (bounded error raster); the generalizer runs on coordinates and heights scaled by eps/16, so its fixed 2 m error raster is eps/8. Landmarks (h >= 28 m, node top 5% by h*sqrt(area)) are kept as themselves, at most one per 16x16 bucket of the node tile. Per-node byte target: 150 KB gzip mesh (about 2,000 footprint vertices with this baker). Over it, the least voluminous features (area x height) are dropped, landmarks and towers included, so a 70 m slab outranks small houses but not a large block. Landmark-first and tower-first orders (h >= 28 m by height band, then volume) were measured on the Gosan/Busan scratch build: in the Busan core up to 171 landmarks per z13 node, plus the other h >= 28 m features, alone fill the budget and every low-rise block is dropped; a tower that is still dropped is charged by the vertical term below, so its node refines earlier. Their counts are folded into the nearest kept feature; each drop costs max(its 2D distance to the kept coverage plus its radius, capped at 2 x the level's start eps as the regional child error; how far its source roofs rise above the nearest kept feature's roof, each at most its own height so terrain slope is not counted, uncapped), so a node that drops much, or drops anything tall, refines earlier instead of standing in as complete. Every input is counted in exactly one output feature (checked: `HLOD coverage loss`); each feature carries summed `componentCount`/`buildingAnchorCount` (component0 only, so multi-part buildings are not double-counted), its members' minimum ground and maximum roof and real footprint area. These source extremes include the folded drops: `sourceMaxRoof` can sit above the feature's drawn roof (a dropped tower nearby) and is carried up as such, so an ancestor that drops the feature again compares that roof with its own nearest kept roof (conservative). Existing leaf geometry retains every component and hole. The coarse B3DM reuses the exact mesh baker and neutral glTF material, adding only batch-table metadata: the counts, each feature's footprint bbox (`west/south/east/north`, degrees) and `lodBlock` (1 when the feature's geometry was merged from more than one component; a single building that only carries folded counts of dropped features stays 0, so the runtime still bbox-tests and counts it). The runtime uses these as for a re-LOD root: blocks are never hidden for the site and not counted as buildings, single components are bbox-tested, and v2 nodes stay visible as stand-ins while their children load (only legacy v1 boxes, which lack `lodBlock`, are hidden then).

Errors are measured, not assumed: z13 error = max(own error against the real footprints, regional root `geometricError` clamped to 2 × z13 eps); above z13 error = max(children) + own error against the children's content, so it is monotone. The clamp keeps one broken regional root (e.g. a 3,634 m bake root) from inflating every ancestor; z13 is already measured against the source, so the child value only orders refinement. Hierarchy: z5–z10 are inline in `tileset.json`; each z11 node is one `nodes/11-x-y.json` holding z11–z13 inline with external links to the regional tilesets, so root → region is three JSON fetches. Intermediate summaries are stored separately. Every z11-z13 node has renderable coarse content; every node has `REPLACE` refinement and at most four children. Runtime integration is deliberately not enabled here.

Each node mesh uses an absolute ECEF ENU frame. An inline child carries `inverse(parentENU) × childENU`, so its computed transform is its own frame; an external reference (z11 file or regional tileset) carries `inverse(parentENU)`, resetting to ECEF for the referenced root's absolute frame. Bounds use conservative ECEF spheres, represented in the node's ENU coordinates; reference bounds are ECEF. Spheres include child spheres and all coarse vertices, and therefore triangle interiors—even long chords below the ellipsoid. A geographical min-height box alone would not safely cover those chords.

Specification references: [OGC 3D Tiles transforms and external tilesets](https://docs.ogc.org/cs/18-053r2/18-053r2.html), [Cesium refinement reference](https://raw.githubusercontent.com/CesiumGS/3d-tiles/main/3d-tiles-reference-card.pdf).

Validation: `bun test tools/ngii-global-hlod.test.ts` checks real-world transform composition, exact component/building coverage, landmark balance, the byte target, the regional error clamp, B3DM count extensions without GLB/material changes, composed inline frames, parent/child containment, three-hop JSON depth, and byte SHA readback failure. Candidate sample coverage must be reported separately from nationwide source completion.

The regional input packing must be `gzip6-mesh-and-metadata-v1`. Footprint metadata is decompressed only after encoded/decoded size and SHA verification. Ancestor meshes are deterministic gzip `.b3dm.gz` payloads with the same geometry; summaries and tile JSON remain plain. The service route supplies `Content-Encoding: gzip` for meshes and retains byte ranges for PMTiles.
