# Editor native design execution: source-backed next units

2026-10-04. Read-only investigation of the ARR source and current Editor consumers. This is an implementation plan, not evidence that native mass generation is already migrated. ARR and AG must cease being runtime dependencies; reusable agents remain external under `D:/Data/25_ACE/agents`.

## The next unit

Implement **project-bound native job creation and retrieval with an immutable, validated optimization specification**, followed directly by **one complete additive SSIEA execution path**. Do not substitute another archive viewer or PLANM diagnostic for this work. Do not advertise the first additive execution as the full MAAS portfolio engine.

Creation is independently useful: the original `ARR/backend/design/views.py:create_job` persists a specification and returns HTTP 202; despite its docstring it does not start a runner. Preserve that distinction in Editor. A created job is not an accepted/completed architectural solution.

## Implementable sequence and ownership

1. **Specification + durable creation, with a real API consumer.** Add pure `modules/design/job_spec.py` (source constraint/default-spec behavior and bounded validation), `native_repository.py` (versioned SQLite jobs with atomic creation and immutable canonical payload hash), and `native_service.py` (project-bound create/get/list). Root API composes through existing DesignAccess; existing project design UI submits an explicit site/analysis/spec and displays the saved specification and created status. Preserve supplied options and original geometry. Reject nonfinite/bool-as-number values, missing/duplicate output definitions, invalid gene ranges, unsupported algorithm and unbounded work budgets. Reject unsupported features explicitly; no fallback to additive for misspelled algorithm. Repeat identical request returns same job; changed payload for that identity conflicts. This first commit must not offer a working Run action before a worker exists.
2. **Complete additive computation and execution.** Add narrowly scoped `modules/design/optimization/{genome,ssiea,ranking,evaluator,repair,renderer}.py` and a worker adapter. Port source additive builder plus used shared metric/repair/shape code as a coherent closure. Persist queued intent before starting work; claim a job atomically, record attempt and owner lease, append numbered events, persist candidates and terminal success together. Poll/SSE only read persisted events and support replay after sequence; opening a page never starts generation. Cancel records intent and worker acknowledges at a generation boundary. If killed without an optimizer-state checkpoint, mark the attempt interrupted and support explicit restart; do not claim continuation from generation N. A global dictionary is not execution ownership. Run workers hidden, using the existing service lifecycle entrypoint conventions.
3. **Additional source algorithms and all-mode.** Port remaining gene/builders with per-algorithm parity fixtures, then MultiAlgoRunner combination semantics. Give each worker independent RNG state and candidate IDs; source shared-global random and swallowed per-algorithm exceptions must not become nondeterministic completion claims. Persist partial failures and require an explicit aggregate completion policy. Source all-mode budgets default to generations 80, islands 5, population 20, with caller overrides.
4. **Full MAAS and shared-agent dependencies.** Migrate this separately from the numerical optimizer; see the closure below. Typed provider/agent adapters remain replaceable and external calls are recorded. Only expose a capability once that exact path and its evidence gates run without ARR/AG roots.

The proposed filenames in steps 1–2 are new ownership boundaries, not existing implemented modules. Keep the native API under the existing project design router; do not add a second application or a backend/arr copy.

## Full MAAS is a separate, larger closure

`views.py:_maas_client_event` first runs ten seed algorithms, then invokes `design.maas.legal_mesh_optimizer.generate_legal_mass_variants` with the seed, site, constraints, building type, envelope, PNU and parking options, requesting up to 18 variants. It replaces the final client Pareto front with floorwise variants and selects a best candidate using parking evidence. Original exception/no-variant fallback returns the untransformed event: Editor must expose that outcome explicitly rather than call raw boxes a completed MAAS result.

`backend/design/maas/legal_mesh_optimizer.py` imports legal envelope/floor stacks, seed library, morphology/grammar/component graph/interpreter, MassDSL island evolution and critic loop, final floorwise legal revalidation, source-volume coherence, integer projection, diversity/quota selection, parking requirements/strategy/stage, quality/program/performance evidence, preference/VLM callbacks, LLM architect/proposals, mass-brain shadow outcomes and agent reviews. `backend/design/maas/single_execution/pipeline.py:execute_single_mass` and `resolve_single_execution_replay` are another real execution/replay contract, not equivalent to the archived execution catalog. These require a dependency inventory and fixtures per source entrypoint before porting, not a re-export of the giant source module.

Source plan `ARR/docs/superpowers/plans/2026-07-28-ten-alternative-mass-portfolio.md` requires at least ten alternatives (full target twenty), deterministic floor/law/FAR/parking gates before paid VLM, exact-solid VLM evidence, and an actual LLM-authored typed GeometryProgram/AST among publishable candidates. A small seeded optimizer smoke test cannot establish this portfolio. GPT Image is downstream elevation treatment of the selected mass in that plan, not a replacement mass generator. These source obligations remain open after steps 1–3.

## Required parity and durability evidence

- Specification differential fixtures: missing/custom specs; every supported building-type objective and floor height; constraints merged into output order; all caller option overrides; municipal coverage unavailable; height-derived floor bounds; area/width thresholds; holes and explicit multipart policy. Compare complete canonical spec, not only gene count.
- Single algorithm differential fixtures: identical injected random stream/seed and tiny bounded budgets; initial evaluation versus subsequent steps, BLX/DE options, normalized penalties, migration, best/Pareto membership, candidate identity and ordered metrics. Run original source in isolated test loading only; Editor runtime must not import it.
- Geometry fixtures: concave/hole sites, setbacks, FAR/BCR/floor/height repair, sunlight envelope and unavailable envelope; compare areas, floor counts, metric vectors and resulting geometry within stated projection tolerance. Evaluated and rendered results must agree. Invalid/empty footprints remain rejected, not zero-valued successes.
- Lifecycle fixtures: duplicate submit/run from concurrent callers; payload mismatch; actor/project/revision isolation; cancellation queued/running; evaluator failure; persistence failure before terminal success; service restart during a generation; event replay without rerunning; immutable result retrieval with source ARR folder unavailable. Injected worker/provider failures must remain visible.
- First actual vertical verification: create a bound job through Editor HTTP, execute additive with bounded budget, reload progress/results, inspect saved geometry and exact input hash, cancel a second job, restart a interrupted attempt. Record artifacts and process cleanup. This proves only the enabled algorithm, not every source generation branch.

## Current limit

This investigation performed no native generation run and changed no source implementation. Existing archive preservation and selected-mass PLANM handoff are useful integration evidence, but neither means the original optimizer or full MAAS execution has moved into Editor. ARR/AG directory removal remains gated on the remaining live entrypoint inventory and independent source-unavailable execution tests.
